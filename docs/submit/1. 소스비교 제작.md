## 1. 개요

PB(구버전, Pro\*C/C) 시스템을 PB5(신버전, Java/XML)로 전환하는 과정에서, **전환 전·후 소스가 동일한 업무 로직을 수행하는지**를 사람이 눈으로 비교·검증해야 한다. 기존에는 두 소스를 각각 열어 수작업으로 대조했기 때문에 시간이 많이 들고 누락·오판이 발생했다.

본 도구는 **PB 소스와 PB5 소스를 한 화면에서 나란히 비교**하고, **메소드 단위 이동·접기**, **라인별 토론(코멘트)** 기능으로 검증 작업을 표준화·효율화하기 위해 제작되었다.

## 2. 추진 배경

- PB → PB5 마이그레이션 물량이 많아 수작업 대조의 한계가 명확함.
- 검증 결과(확인 요청/이슈)를 소스 라인에 직접 남기고 담당자 간 주고받을 수단이 필요함.
- 대분류·중분류·프로그램명 체계로 비교 대상을 빠르게 찾을 수 있어야 함.

## 3. 목표 및 기대효과

| 구분 | 내용 |
|---|---|
| 목표 1 | PB(C/Pro\*C)와 PB5(Java/XML) 소스를 좌·우 동시 비교 |
| 목표 2 | 메소드 인식 기반의 빠른 이동·접기로 대조 시간 단축 |
| 목표 3 | 라인 단위 토론(코멘트)로 검증 이슈를 소스에 귀속하여 관리 |
| 기대효과 | 검증 시간 단축, 누락 감소, 검증 이력의 추적성 확보 |

## 4. 적용 범위

- **PB(구버전)**: Pro\*C/C 소스(`.pc`, `.c`, `.h`)
- **PB5(신버전)**: Java 소스(`.java`), MyBatis 매퍼(`.xml`), SQL(`.sql`)
- **비교 대상 관리**: 대분류 → 중분류 → 프로그램명 3단계 카탈로그
- **검증 협업**: 라인별 스레드/댓글, 상태(PB 확인 / PB5 확인 / 해결)

## 5. 주요 기능 요약

| # | 기능 | 설명 |
|---|---|---|
| 1 | 비교 대상 선택 | 대분류·중분류·프로그램명으로 좌(PB)/우(PB5) 소스 자동 로드 |
| 2 | 좌·우 비교 뷰 | 문법 하이라이팅 + 대용량 가상 스크롤 |
| 3 | 메소드 인식 | C/Java 소스에서 메소드(함수) 자동 추출 |
| 4 | 메소드 점프 | 프로그램ID가 `파일.메소드` 형태면 해당 메소드로 자동 이동, 좌·우 대응 메소드 이동(Alt+클릭) |
| 5 | 메소드 접기 | 메소드 단위 접기/펼치기, 전체 접기/펼치기 |
| 6 | 동기 스크롤 | 좌·우 스크롤 연동(켜기/끄기) |
| 7 | 라인 토론 | 라인별 스레드/댓글, 상태별 마커 색상, 본문+답글 |
| 8 | 인코딩 자동 복원 | EUC-KR(CP949) PB 소스 한글 깨짐 자동 복원 |
| 9 | 가독성 옵션 | 글자 크기 조절, 좌·우 패널 너비 조절 |

## 6. 기술 스택

| 구분 | 기술 |
|---|---|
| 프론트엔드 | Vite, React, TypeScript, Tailwind CSS, Shiki(하이라이팅), TanStack Virtual(가상 스크롤) |

## 7. 산출물

- 소스 비교검증 웹 도구(프론트엔드 `comparsionV2`)
- 검증 협업 API 서버(백엔드 `comparsion-be`)
- 개발/설계/구현/검증 문서(본 docs/submit 일체)

## 8. 비교 흐름 (요약)

```
[대분류 선택] → [중분류 선택] → [프로그램명 선택]
        ↓
[좌: PB 소스 로드]   [우: PB5 소스 로드]   (프로그램ID → parser → 실제 파일 매칭)
        ↓
[하이라이팅 · 메소드 인식 · 자동 점프]
        ↓
[라인 토론(코멘트)로 검증 이슈 기록 · 상태 관리]
```
