## docs/ai 가이드 기준 코드 리뷰 및 수정 (High + Medium)

가이드(코딩/리팩토링/성능/REST/폴더구조/UI-UX) 기준으로 BE(NestJS+OracleDB)·FE(React) 전체를 리뷰하고 심각도 우선순위로 수정. 리팩토링 가이드대로 green 기준선 확인 → 하나씩 변경 → 빌드/테스트/스모크/프리뷰로 전후 검증.

### High
- **H1 메시지 수정/삭제 트랜잭션 버그**: `discussion-message.service.ts` getMessage 의 `Promise.all` 을 순차 await 로 변경. @Transactional(update/remove) 안에서 단일 커넥션 동시 실행 → node-oracledb NJS-087 로 실 Oracle에서 확정 실패하던 것을 제거. 404 의미(스레드/메시지 없음) 보존.
- **H2 배포 설정 → mock 전환**: `config/index.ts` 를 `OracleAppConfig`(접속정보 미완성 스켈레톤) → `StaticAppConfig`(profile=MOCK) 로 교체. DB 없이 인메모리 목으로 부팅. 실 Oracle 복귀 절차를 주석화. (BE 테스트 `Pool not initialized` 사전 실패도 해소)
- **H3 스레드 목록 전체 스캔 제거**: `GET /services/:id/discussion-threads` 가 전체 스레드 조회 후 JS 필터하던 것을, repository.findAll(serviceId) 로 SQL WHERE 필터. 응답(배열) 계약은 그대로. 죽은 대소문자 다중키 분기 정리.
- **H4 파서(Impl 누락)**: 요청에 따라 **변경하지 않음**.
- **H5 키보드 접근성**: `CommentBoard` 스레드 헤더 div 에 role/tabIndex/aria-expanded/onKeyDown(Enter·Space) 추가 → 키보드로 스레드 펼침/접기 가능. 내부 버튼 중복 토글은 target===currentTarget 가드로 차단.

### Medium

- **응답 압축**: `compression()` gzip 미들웨어 추가. (신규 의존성: compression)
- **REST 상태코드**: 3개 DELETE 엔드포인트 → 204 No Content(멱등).
- **타입 안전성**: nextChecker `any`→`string` + guard clause(null 시 400), 불필요한 `(dto as any)` 제거, FE discussionService/checklistService 의 `any` 매핑을 응답 DTO 인터페이스 + 열거형 가드로 교체(유령 값 차단).
- **테스트 가능성**: discussionService.getMessages 의 `new Date().toLocaleString()` 폴백 제거(비결정적 → 빈 문자열, 순수 매핑).
- **UX 일관성(ESC 닫기)**: ChecklistBoard 카드 모달에 ESC 닫기 추가. Checklist 슬라이드 패널은 CodeComparator 의 기존 중앙 ESC 핸들러에 편입(SQL 패널과 동일 방식, '한 번에 하나' 우선순위 보존). ※ 적대적 재검증에서 SqlSlidePanel 에 별도 ESC 리스너를 붙였던 것이 중앙 핸들러와 이중 처리되는 회귀로 확인되어 되돌리고, ESC 처리를 window 리스너 한 곳(CodeComparator)으로 통일함.
- **죽은 코드/빌드 위생**: 미사용 `db/ConnectionPool.ts` 삭제, config 미사용 import 제거, CodeComparator 디버그 console.log 제거, tsconfig(.build) 에 빌드 산출물 `be_next` 제외(사전 빌드 breakage 해결).

### 외부 API 변경 (중요)
- **변경 있음**:
  - `DELETE /services/:id`, `DELETE .../discussion-threads/:id`, `DELETE .../messages/:id` : 응답 `200 + 영향행수` → **`204 No Content`** (FE 는 response.ok 만 확인 → 영향 없음).
  - 모든 POST/PATCH: 유효성 검증 강화 → 형식 오류 시 **400**(class-validator 메시지), DTO 미선언 필드는 응답에서 제거(whitelist). FE 전송 바디는 전부 DTO에 대응됨을 확인.
- **변경 없음**: `GET /services/:id/discussion-threads` 응답 형태(배열) 동일(내부 쿼리만 최적화). URL·메서드 체계 동일.
