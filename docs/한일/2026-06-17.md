## 체크리스트 404 디버깅 — 빈 serviceId 가드 + 깨진 create.sql 복구 (사용자 보고)

- 증상: "오라클쪽 체크리스트 연결이 안 됨, 404, serviceId 추정".
- 근본원인(실측): 라우트/baseURL 정상. `GET /services/a/checklist`→200, **`GET /services//checklist`(빈 serviceId)→404 "Cannot GET"**, `GET /services/checklist`(붕괴)→404 "Service 'checklist' not found"(services findOne). 즉 **serviceId 가 비면 체크리스트 URL이 `/services//checklist` 가 되어 404**. 사용자 추정 적중.
- 수정1(FE, `checklistService.ts`): `getChecklist`/`updateChecklistItem` 에 빈 serviceId 가드 추가 → 빈 값이면 요청 자체를 안 보냄(방어). 패널 load() 가드와 합쳐 이중 방어.
- 수정2(`create.sql`): 확인 중 발견 — 체크리스트 DDL이 **깨져 있어 실행 불가**였음(`check_point_id NUMBER` 뒤 콤마 누락, FK 없음, 하단 인덱스/COMMENT가 옛 이름 `comparsion_checkList` 참조). → `comparsion_check_point`(+sort_order) / `comparsion_check_list`(FK·UNIQUE) 유효 DDL로 복구하고 백엔드 레포와 컬럼 일치. 사용자의 의도 변경(service_id VARCHAR2(200), detail NOT NULL, file_name 유지)은 보존.
