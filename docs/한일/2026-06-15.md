## C(PB) 메소드 인식 — 중간부터 누락되는 depth 어긋남 수정

- 증상: 처음 몇백 줄은 인식하다가 중간부터 못하고 끝에서 일부 회복(위치 의존). → brace depth가 어긋나 `topLevelDepth===0` 게이트가 막히면 그 지점부터 탐지 중단, 뒤에서 `}`들로 depth가 0으로 돌아오면 재개되는 전형적 desync.
- 재현(스트레스 스크립트): 멀티라인 문자열(`\` 연속)의 닫히지 않은 `{` 가 depth를 고정 → 이후 함수 전부 누락 확인. (`#if 0` 비활성 코드의 불균형 중괄호도 같은 부류)
- 수정(`extractCMethods`): C 함수/구조체는 거의 항상 **컬럼0에서 시작**하므로 탐지 게이트를 `topLevelDepth===0 || 컬럼0`으로 확장 → depth가 어긋나도 컬럼0 함수는 계속 인식.
- 검증: 스트레스 케이스 전부 통과, 단위테스트 69건 통과, `vite build` 성공. 라이브: mock C 파일 M:6 유지(과탐지 없음). 멀티라인 문자열 회귀 테스트 추가.
- 별도 발견(미수정): Java 익명 클래스 본문의 메소드가 초과 인식됨 — 누락이 아닌 과탐지라 사용자 증상과 별개. 필요 시 추가 수정.
