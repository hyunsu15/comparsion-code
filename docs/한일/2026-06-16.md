## C(PB) 메소드 인식 depth-free 전환 (근본 갈아엎기)

- 배경: 트리거(전처리기/멀티라인문자열/extern "C"/들여쓰기)를 하나씩 막아도 `extractCMethods`가 **전역 brace-depth**에 의존하는 한 desync→'중간 누락' 버그가 반복됨. (Java가 멀쩡한 이유 = depth를 안 씀)
- 변경: 검색/Java처럼 **depth 추적을 완전 제거**하고 '정의 패턴'으로만 탐지 — `detectCFunctionAt`가 (라이브 코드 줄 && `(`/`struct` 포함 && 본문 `{`가 `;`보다 먼저 && 키워드 아님)이면 함수/구조체로 인식. 호출/제어문은 본문 `{` 없음·키워드로, 멀티라인 시그니처 줄은 `skipDetectUntil`로 제외. C는 중첩 함수가 없어 본문 안엔 정의가 없으므로 안전.
- 부수: `topLevelDepth`/`applyBraces` 삭제, `buildCountBrace`→`buildLiveCode`(이름이 의미에 맞게: 지시문·`#if 0`·`#ifdef/#else` 비채택 분기 제외 표시). 구조체는 `struct 이름 {` 정의만 인식하도록 좁혀 변수 선언/초기화(`struct Foo bar = {…}`) 과탐지 제거.

## 함수명과 여는 `(` 가 다른 줄이면 메소드 인식 실패 버그 수정 (사용자 보고)
