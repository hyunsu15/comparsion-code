# 리팩토링 및 성능개선 가이드

리팩토링이나 성능개선시 다음과 같은 흐름으로 동작한다.

---

# 1. Public 메소드 및 Export 메소드 점검하여, 사용자에게 안내한다.

외부에 공개되는 API는 변경 영향도가 크므로 가장 먼저 확인한다.

## 점검 항목

### 이름이 적절한 책임을 표현하는지

- 메소드명만 보고도 동작을 유추할 수 있어야 한다.
- 이름과 실제 동작이 일치해야 한다.
- 여러 책임을 수행한다면 분리를 고려한다.
- 적절한 책임이 아니라고 판단되면, 사용자에게 제안한다.

### 하나의 명확한 역할만 수행하는지

- 조회, 검증, 저장, 변환 등의 역할이 혼재되어 있지 않은지 확인한다.
- 하나의 변경 이유만 가지도록 설계한다.

### 반환 타입과 파라미터가 의도를 명확하게 표현하는지

- 반환값만 보고도 결과를 이해할 수 있어야 한다.
- 의미 없는 boolean 파라미터 사용을 지양한다.
- 파라미터 수가 많다면 객체로 묶는 것을 고려한다.

### 외부에 노출할 필요가 없는 메소드가 공개되어 있지 않은지

- 사용 범위를 최소화한다.
- private, protected 또는 내부 모듈로 숨길 수 있는지 검토한다.

### 예외 처리 방식이 일관성 있는지

- 동일한 오류를 서로 다른 방식으로 처리하지 않는지 확인한다.
- 예외를 삼키거나 무시하는 코드가 없는지 확인한다.

### 사이드 이펙트가 명확한지

- 조회 메소드가 데이터를 수정하지 않는지 확인한다.
- 메소드 이름만으로 예상하지 못한 동작이 없는지 확인한다.

### 테스트하기 쉬운 구조인지

- 외부 시스템 의존성이 과도하지 않은지 확인한다.
- Mock 없이도 테스트 가능한 영역을 늘릴 수 있는지 검토한다.
- 시간, 랜덤값, 외부 API 등의 의존성을 주입받는지 확인한다.

### 호출하는 입장에서 사용하기 쉬운 인터페이스인지

- 사용 방법이 직관적인지 확인한다.
- 암묵적인 호출 순서 의존성이 없는지 검토한다.

#2 현재 동작을 보존하기 위한 테스트 코드를 작성한다.
- 반환값
- 예외
- 부수효과
- 이벤트 발생 여부
- 도메인 규칙
와 테스트 가이드.md 내용을 참고한다.

#3 Public 및 Export 메소드의 시그니처는 변경하지 않는다.
- 함수명 변경 금지
- 파라미터 변경 금지
- 반환 타입 변경 금지

#4 내부 구현만 개선한다.
- 중복 제거
- 가독성 향상
- 의존성 정리
- 복잡도 감소

#5 작성한 테스트가 모두 통과해야 한다.

#6 성능 개선 작업인 경우 성능 지표를 측정하고 결과를 제시한다.
