## 1. 검증 개요

소스 비교 도구의 **핵심 로직(메소드 인식·점프)**, **빌드 무결성**, **주요 기능(카탈로그·비교·토론)**, **발견 결함의 조치**를 검증하였다. 핵심 로직은 단위 테스트(Vitest)로 고정하고, 화면 동작은 실제 구동(라이브)으로 확인하였다.

## 2. 검증 환경

| 구분 | 내용 |
|---|---|
| 프론트엔드 | Vite Dev(:5173), 단위 테스트 Vitest |
| 백엔드 | NestJS Mock 프로파일(:50004) — 인메모리 리포지토리 |
| 검증 방식 | 단위 테스트 / 빌드 / 라이브 구동(브라우저 DOM·콘솔·네트워크 확인) |

## 3. 단위 테스트 (Vitest)

핵심 순수 함수(`methodJump.ts`, parser)를 대상으로 행동 기반 + 엣지 케이스를 검증.

| 영역 | 대표 케이스 | 결과 |
|---|---|---|
| 점프 대상 도출(`extractMethodFromFileName`/`resolveJumpTargets`) | `파일.메소드`→메소드, `.pc/.java`→null, 좌·우 공유, 빈값/점 위치 엣지 | 통과 |
| 메소드 매칭(`findMethodLineByName`/`areSameMethodName`) | snake_case ↔ camelCase 교차 매칭, 미존재 시 null | 통과 |
| 파일명 도출(`resolveProgramFileName`) | 서비스(`_APS`/`Service`)·메소드 단위 보존·default 보존 | 통과 |
| Java 인식(`extractMethods`) | K&R/Allman/제네릭/멀티라인/생성자/어노테이션/제외대상 | 통과 |
| C 인식(`extractCMethods`) | K&R·Allman/프로토타입 제외/struct 파라미터/#define 제외/xml·sql | 통과 |
| Transfer 메소드 parser | `.pc`/`.c` 접미사 제거(대소문자), 접미사 외 보존 | 통과 |

- 총계: **52개 케이스 전부 통과**(`npm test`).

## 5. 기능 검증 (라이브 구동)

Mock 백엔드 + Dev 서버로 실제 화면을 구동하여 확인.

| 기능 | 검증 내용 | 결과 |
|---|---|---|
| 카탈로그 선택 | 대분류→중분류→프로그램명 선택 시 좌·우 소스 자동 로드 | 정상 |
| 메소드 인식 | 좌(PB/C)·우(PB5/Java) 메소드 목록 추출(콘솔 로그로 확인) | 정상 |
| 메소드 점프 | `파일.메소드` 형태에서 좌·우 해당 메소드로 이동 | 정상 |
| 토론 마커 | 상태별 색상(PB=indigo, PB5=emerald, 해결=회색) 표시 | 정상 |
| 마커 클릭 | 클릭 시 해당 스레드만 열림, 다른 마커 유지 | 정상 |
| 스레드 종료 | 종료한 마커만 사라지고 나머지는 유지 | 정상 |
| 댓글/답글 작성 | 작성 후 마커 유지 + 신규 마커 추가(Mock) | 정상 |

## 6. 발견 결함 및 조치

| # | 결함 | 심각도 | 조치 | 상태 |
|---|---|---|---|---|
| D-1 | PB 메소드/프로그램명 점프 미동작 | 높음 | 좌·우 점프 대상 공유, pb 분기 대칭화 | 완료 |
| D-2 | Java 메소드 인식 누락(스타일별) | 높음 | 괄호/중괄호 추적 스캐너로 재작성 | 완료 |
| D-3 | PB 메소드 인식 오류(struct/#define/익명) | 중간 | 함수명 추출/전처리기·익명 구조체 처리 보강 | 완료 |
| D-4 | 점프 locator 확장자 혼입 | 중간 | 매핑값 `.pc`/`.c` 제거 | 완료 |
| D-5 | (Oracle) 댓글/답글 작성 시 마커 사라짐 | 높음 | 단일 트랜잭션 커넥션의 `Promise.all` 동시 실행 → 순차 await 로 변경 | 조치 완료(실DB 재확인 필요) |

- 단위 테스트 52/52 통과, FE/BE 빌드 성공.
- 카탈로그·비교·메소드 인식/점프·토론(마커/스레드/댓글) 기능 라이브 정상.
