## 1. 설계 개요

- **프론트엔드(SPA)**: 비교 화면·메소드 인식·점프·접기·토론 UI를 담당.
- **백엔드(API)**: 비교 대상 카탈로그(services)와 토론(thread/message)을 제공.
- **소스 파일**: 프론트엔드 자산(`src/assets/code`)에 포함하여, 프로그램ID로 지연 로딩.
- 설계 원칙: **화면(검증) 기준 설계**, **응집성 있는 모듈 분리**, **확장 가능한 parser 전략**.

## 2. 시스템 아키텍처

```
┌──────────────────────────── 브라우저 (FE: comparsionV2) ─────────────────────────────┐
│  CodeComparator (상태/오케스트레이션)                                                  │
│   ├─ 카탈로그 선택(대/중/프로그램)  ── discussionService ──▶  [BE /services]            │
│   ├─ 소스 해석(Link.ts) ── resolveSourceContent ──▶ assets/code (지연 로딩, 인코딩복원) │
│   ├─ methodJump.ts (메소드 추출/점프 대상 도출/parser 연동)                            │
│   ├─ CodeBlock (Shiki 토큰 + TanStack 가상 스크롤 + 마커/접기)                          │
│   └─ 토론 패널/입력(스레드·댓글) ── discussionService ──▶ [BE /discussion-threads]      │
└───────────────────────────────────────────────────────────────────────────────────────┘
                                   │ REST(JSON), CORS
┌──────────────────────────── 서버 (BE: comparsion-be, NestJS 헥사고날) ────────────────┐
│  port/in (Controller, DTO)  →  Service  →  port/out (Repository: Oracle | Mock)         │
│  @Transactional (AsyncLocalStorage 단일 커넥션) · oracledb Thin · CLOB=String           │
└───────────────────────────────────────────────────────────────────────────────────────┘
```

## 3. 데이터 모델

> 저장은 정규화(A 포맷), 응답은 첫 메시지를 JOIN 한 합본(B 뷰)으로 내려 프론트가 단순하게 동작.

### 3-1. comparsion_services (비교 대상 카탈로그)

| 컬럼 | 설명 |
|---|---|
| service_id | 프로그램명(비교 대상 선택 키) |
| big_category | 분류(대분류) |
| middle_category | 업무(중분류) |
| code_kind | `pb`(왼쪽) / `pb5`(오른쪽) |
| file_name | PB 또는 PB5 프로그램ID |

- (service_id, code_kind) **복합 PK** — 서비스 1개당 pb/pb5 2행.

### 3-2. comparsion_discussion_thread (스레드 메타데이터)

| 컬럼 | 설명 |
|---|---|
| id | PK |
| status | `CHECK_PB` / `CHECK_PB5` / `RESOLVED` (마지막 글쓴이에서 파생) |
| code_kind | 마커가 찍히는 코드 쪽(pb/pb5) |
| service_id | 대상 프로그램 |
| location | 줄 번호 |
| resolved_at / created_at | 해결/생성 시각(KST) |

### 3-3. comparsion_discussion_message (글 본문 + 답글)

| 컬럼 | 설명 |
|---|---|
| id | PK (가장 작은 id = 스레드 본문) |
| thread_id | FK(스레드), ON DELETE CASCADE |
| writer_role | 작성자 측(pb/pb5) |
| writer_name | 작성자 이름 |
| content | 내용(CLOB) |
| created_at | 생성 시각(KST) |

- **상태 파생 규칙**: pb가 글 작성 → `CHECK_PB5`, pb5가 글 작성 → `CHECK_PB`. 상태 갱신은 *스레드 생성*과 *메시지 추가* 두 지점에서만 수행(드리프트 방지).

## 4. 화면 설계

| 영역 | 구성 |
|---|---|
| 헤더 | 플랫폼 토글(PB/PB5), 작성자명 입력, 글자 크기 |
| 비교 세트 선택 | 대분류 · 중분류 · 프로그램명 · 동기 스크롤 토글 |
| 좌측 패널(PB) | 파일명, 라인수/메소드수, 코드 뷰(접기/마커), 전체 접기 |
| 우측 패널(PB5) | 좌측과 동일 구성, 드래그 핸들로 좌·우 너비 조절 |
| 오버레이 | 스레드 보기 / 댓글 입력 / 스레드 종료 확인 / 토스트 |

- **상호작용 규약(코드 라인)**: `클릭=접기`, `Alt+클릭=대응 메소드로 점프`, `Shift+클릭=댓글 작성`, `마커 클릭=스레드 열기`.

## 5. 주요 컴포넌트 설계

| 모듈 | 책임 |
|---|---|
| `CodeComparator.tsx` | 전역 상태·데이터 로딩·이벤트 오케스트레이션(컨테이너) |
| `CodeBlock.tsx` | Shiki 토큰 렌더 + 가상 스크롤 + 접기/마커 + `scrollToLine` 핸들 |
| `methodJump.ts` | 메소드 추출(C/Java) · 점프 대상 도출 · 좌우 메소드 매칭 · parser 연동 (순수 함수, 테스트 대상) |
| `Link.ts` | 프로그램ID → 실제 자산 파일 매칭, 지연 로딩, EUC-KR 복원 |
| `parser/*` | 대분류별 file_name → 실제 파일명/메소드 도출 전략 |
| `discussionService.ts` | 백엔드 REST 연동(서비스/스레드/메시지) |

## 6. Parser 전략 설계 (대분류 기반)

> file_name(프로그램ID)을 실제 파일/메소드로 해석하는 책임을 전략 패턴으로 분리. 새 규칙은 구현체 추가만으로 확장.

| 구분 | Parser | 규칙(예) |
|---|---|---|
| PB | PbServiceParser | `<id>` → `<id>_APS` (서비스) |
| PB | PbSqlParser | `<id>` → `<id>.sql` |
| PB | PbTransferFileNameParser / MethodParser | 매핑표 기반(파일/메소드 단위), `.pc`·`.c` 확장자 제거 |
| PB | PbDefaultParser | 가공 없이 그대로(fallback) |
| PB5 | Pb5ClassImplMethodParser | `<id>` → `<Class>Impl.<method>` (메소드 단위) |
| PB5 | Pb5ClassImplParser / ServiceParser / XmlParser | `<id>Impl` / `<id>Service` / `<id>.xml` |
| PB5 | Pb5DefaultParser | 그대로(fallback) |

- 대분류↔Parser 매핑은 `config/categoryMap`(환경변수 주입)으로 운영값을 외부화.
- `파일.메소드` 형태는 확장자를 붙이지 않고 보존하여 다운스트림 점프 locator로 사용.

## 7. API 설계 (REST)

| 기능 | Method | URL |
|---|---|---|
| 비교 대상 목록 | GET | `/services` |
| 스레드 목록(서비스별) | GET | `/services/{serviceId}/discussion-threads` |
| 스레드 생성 | POST | `/services/{serviceId}/discussion-threads` |
| 스레드 종료(해결) | POST | `/services/{serviceId}/discussion-threads/{id}/close` |
| 메시지 목록 | GET | `/services/{serviceId}/discussion-threads/{threadId}/messages` |
| 메시지 작성 | POST | `/services/{serviceId}/discussion-threads/{threadId}/messages` |

- 응답: 스레드 조회는 첫 메시지(content/writer)를 JOIN 한 B 뷰. `RESOLVED`는 목록에서 제외(해결된 스레드 비표시).

## 8. 비기능 설계

| 항목 | 설계 |
|---|---|
| 성능 | 대용량 소스 대응 가상 스크롤(보이는 라인만 렌더), 소스 지연 로딩 |
| 인코딩 | PB 소스 UTF-8 우선 → 실패 시 EUC-KR 복원(원본 바이트 fetch) |
| 트랜잭션 | `@Transactional` + AsyncLocalStorage 단일 커넥션, 커밋/롤백 일원화 |
| 운영 보안 | 대분류 매핑값 등 민감정보는 환경변수(.env.*.local)로 분리 |
| 배포 | ncc 단일 번들(oracledb Thin 포함)로 의존성 설치 없이 pm2 구동 |
