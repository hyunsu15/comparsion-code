## 1. 설계 개요

- **프론트엔드(SPA)**: 3개 화면(소스 비교 / 의견 모아보기 / 체크리스트 모아보기)과 코드 뷰·메서드 인식·검색·토론 UI를 담당.
- **백엔드(API)**: 비교 대상 카탈로그(services), 토론(thread/message), 체크리스트(check point/list)를 제공.
- **소스 파일**: 프론트엔드 자산(`fe/src/assets/code`)에 두고, **파일명(basename)** 기준으로 매칭하여 지연 로딩.
- 설계 원칙: **화면(검증) 기준 설계**, **응집성 있는 기능 폴더 분리**, **확장 가능한 parser 전략**, **순수 로직은 UI와 분리해 단위 테스트로 고정**.

## 3. 데이터 모델

> 저장은 정규화(A 포맷), 응답은 첫 메시지를 JOIN 한 합본(B 뷰)으로 내려 프론트가 단순하게 동작. 상세는 [be/데이터.md](../../../be/데이터.md), DDL은 [be/create.sql](../../../be/create.sql).

### 3-1. comparsion_services (비교 대상 카탈로그)

| 컬럼 | 설명 |
|---|---|
| service_id | 프로그램명(비교 대상 선택 키) |
| big_category | 분류(대분류) |
| middle_category | 업무(중분류) |
| code_kind | `pb`(왼쪽) / `pb5`(오른쪽) |
| file_name | PB 또는 PB5 프로그램ID |

- (service_id, code_kind) **복합 PK** — 서비스 1개당 pb/pb5 2행.

### 3-2. comparsion_discussion_thread (스레드 메타데이터)

| 컬럼 | 설명 |
|---|---|
| id | PK |
| status | `CHECK_PB` / `CHECK_PB5` / `RESOLVED` (마지막 글쓴이에서 파생) |
| **opinion_type** | **의견 유형 — MISMATCH/OMISSION/EXPLANATION/BUSINESS_CHECK/ETC. 생성 시 필수(앱 레벨 강제), 이후 불변 (2.0)** |
| code_kind | 마커가 찍히는 코드 쪽(pb/pb5) |
| service_id | 대상 프로그램 |
| location | 줄 번호 |
| resolved_at / created_at | 해결/생성 시각(KST) |

- 인덱스: `service_id`, `resolved_at`.

### 3-3. comparsion_discussion_message (글 본문 + 답글)

| 컬럼 | 설명 |
|---|---|
| id | PK (가장 작은 id = 스레드 본문) |
| thread_id | FK(스레드), ON DELETE CASCADE |
| writer_role | 작성자 측(pb/pb5) |
| writer_name | 작성자 이름 |
| content | 내용(CLOB) |
| **reaction** | **처리 리액션 — REVIEWING/DONE/SKIP (NULL=미설정). 메시지 단위 설정 (2.0)** |
| created_at | 생성 시각(KST) |

- **상태 파생 규칙**: pb가 글 작성 → `CHECK_PB5`, pb5가 글 작성 → `CHECK_PB`. 상태 갱신은 *스레드 생성*과 *메시지 추가* 두 지점에서만 수행(드리프트 방지).
- 스레드 제목에는 **가장 최근 메시지의 리액션**을 "마지막 리액션"으로 파생 표시.

### 3-4. comparsion_check_point (점검 항목 마스터) — 2.0 신규

| 컬럼 | 설명 |
|---|---|
| id | PK |
| check_point | 카테고리(제목) — 같은 값이 여러 문항에 반복 |
| detail | 개별 점검 문항 1개 |
| sort_order | 표시 순서 |

- 모든 프로그램 공통의 **표준 점검 문항** 정의. 프론트는 check_point(제목)로 그룹핑해 카테고리 단위로 접는다.

### 3-5. comparsion_check_list (프로그램별 점검 상태) — 2.0 신규

| 컬럼 | 설명 |
|---|---|
| id | PK |
| check_point_id | FK → check_point.id (ON DELETE CASCADE) |
| service_id | 프로그램명 |
| comment_text | 프로그램별 메모(API 필드명 `comment` — COMMENT 는 오라클 예약어) |
| status | `NONE`/`YES`/`NO`/`NA`/`HOLD` (선택안함/예/아니오/해당없음/판단 보류), 기본 `NONE` |
| update_date | 최종 변경 시각(KST) |

- `UNIQUE(check_point_id, service_id)` — 한 프로그램에 같은 문항 1행(업서트).
- **진행률 규칙**: `YES`/`NO`/`NA` = 판단 완료, `HOLD`/`NONE` = 미판단. 행이 없으면 `NONE` 으로 표시.

## 4. 화면 설계

### 4-1. 소스 비교 탭

| 영역 | 구성 |
|---|---|
| 헤더 | 플랫폼 토글(PB/PB5), 작성자명 입력, 글자 크기, 탭 전환 |
| 비교 세트 선택 | 분류 · 업무 · 프로그램명 · 즐겨찾기(★) 칩 행 |
| 좌측 패널(PB) | 파일명, 라인수/메서드수, 코드 뷰(접기/마커), 전체 접기, 검색 |
| 가운데 분할선 | 동기 스크롤 체인 버튼(클릭 영역 확대) + 드래그 핸들(좌·우 너비) |
| 우측 패널(PB5) | 좌측과 동일 구성 |
| 슬라이드 패널 | 체크리스트(좌) / SQL 대응(우) — ESC로 닫기, 한 번에 하나 |
| 오버레이 | 스레드 보기 / 의견 입력(유형 선택) / 스레드 종료 확인 / 토스트 / 단축키 도움말 |

- **상호작용 규약(코드 라인)**: `클릭=접기`, `Alt+클릭=대응 메서드로 점프`, `Shift+클릭=의견 작성`, `마커 클릭=스레드 열기`, `Ctrl+F=해당 패널 검색`, `매퍼 호출 줄 클릭=SQL 대응 보기`.

### 4-2. 의견 모아보기 탭

| 영역 | 구성 |
|---|---|
| 필터 | 유형(분류)·업무 공유 칩 + 상태 / 의견 유형 / 즐겨찾기 |
| 목록 | 스레드 카드(프로그램명·유형 배지·상태 배지·마지막 리액션·줄 번호), 펼치면 답글 |
| 작성 | 답글 입력, 메시지별 리액션, 수정/삭제(가드 적용), 스레드 종료 |
| 페이징 | 페이지 번호 바(현재 페이지 중심 슬라이딩 윈도우, 기본 20건/페이지) |

- 첫 진입 시 **전체 모아보기**가 기본 선택된다.
- **리액션 권한**: 본인 측(같은 팀) 글에는 리액션할 수 없고, 같은 팀 리액션은 표시하지 않는다.
- **수정/삭제 가드**: 상대 측이 그 글 이후에 답한 경우 수정·삭제 모두 차단(맥락 보존).

### 4-3. 체크리스트 모아보기 탭

- 행 = 프로그램, 열 = 점검 문항. 셀 = 상태 색 + 의견 표시.
- 전체 진행률·미판정 집계, 유형·업무 필터, 대용량(2만 건급) 가상 스크롤, **읽기 전용**(수정은 소스 비교 탭의 체크리스트 패널에서).

## 6. Parser 전략 설계 (분류 기반)

> file_name(프로그램ID)을 실제 파일/메서드로 해석하는 책임을 전략 패턴으로 분리. 새 규칙은 구현체 추가만으로 확장.

| 구분 | Parser | 규칙(예) |
|---|---|---|
| PB | PbServiceParser | `<id>` → `<id>_APS` (서비스) |
| PB | PbSqlParser | `<id>` → `<id>.sql` |
| PB | PbTransferFileNameParser / MethodParser | 매핑표 기반(파일/메서드 단위), `.pc`·`.c` 확장자 제거 |
| PB | PbDefaultParser | 가공 없이 그대로(fallback) |
| PB5 | Pb5ClassImplMethodParser | `<id>` → `<Class>Impl.<method>` (메서드 단위) |
| PB5 | Pb5ClassImplParser / ServiceParser / XmlParser | `<id>Impl` / `<id>Service` / `<id>.xml` |
| PB5 | Pb5DefaultParser | 그대로(fallback) |

- 분류↔Parser 매핑은 `config/categoryMap`(환경변수 `VITE_<클래스명>` 주입)으로 운영값을 외부화. 값이 없거나 미설정이면 개발 폴백값을 사용한다.
- `파일.메서드` 형태는 확장자를 붙이지 않고 보존하여 다운스트림 점프 locator로 사용.

## 7. SQL 대응 설계 (2.0 신규)

PB는 Pro\*C 인라인 `EXEC SQL`, PB5는 MyBatis 매퍼로 SQL이 분리되어 있어 같은 줄에서 대조할 수 없다. 이를 잇는 순수 로직을 `sqlLink.ts` 에 둔다.

1. PB5 Java에서 **매퍼 호출**(예: `acctMapper.insertAccount(...)`)을 인식 → receiver / methodName / mapperType 추출.
2. `import` 구역에서 매퍼 타입의 **namespace**(예: `com.example.acct.AcctMapper`)를 도출.
3. namespace + methodName 으로 **PB5 매퍼 XML 구문**(select/insert/update/delete 의 id)을 찾는다.
4. 같은 SQL 동사(select/insert/update/delete)의 **PB 인라인 EXEC SQL** 구문을 좌측에서 수집한다.
5. 슬라이드 패널에 좌(PB 인라인) · 우(PB5 XML)를 나란히 제시하고, 원 소스 줄로 이동할 수 있게 한다.

## 8. API 설계 (REST)

### 8-1. 카탈로그

| 기능 | Method | URL |
|---|---|---|
| 비교 대상 등록 | POST | `/services` |
| 비교 대상 목록 | GET | `/services` |
| 비교 대상 단건 | GET | `/services/{serviceId}` |
| 비교 대상 삭제 | DELETE | `/services/{serviceId}` (204) |

### 8-2. 토론(스레드/메시지)

| 기능 | Method | URL |
|---|---|---|
| 스레드 목록(서비스별) | GET | `/services/{serviceId}/discussion-threads` |
| 스레드 단건 | GET | `/services/{serviceId}/discussion-threads/{id}` |
| 스레드 생성 | POST | `/services/{serviceId}/discussion-threads` |
| 스레드 수정 | PATCH | `/services/{serviceId}/discussion-threads/{id}` |
| 스레드 종료(해결) | POST | `/services/{serviceId}/discussion-threads/{id}/close` |
| 스레드 삭제 | DELETE | `/services/{serviceId}/discussion-threads/{id}` (204) |
| **전체/분류별 스레드(페이징)** | GET | `/discussion-threads` **(2.0)** |
| 메시지 목록 | GET | `/services/{serviceId}/discussion-threads/{threadId}/messages` |
| 메시지 단건 | GET | `.../messages/{id}` |
| 메시지 작성 | POST | `.../messages` |
| 메시지 수정 | PATCH | `.../messages/{id}` |
| **메시지 리액션 설정** | PATCH | `.../messages/{id}/reaction` **(2.0)** |
| 메시지 삭제 | DELETE | `.../messages/{id}` (204) |

- 스레드 조회 응답은 첫 메시지(content/writer)를 JOIN 한 B 뷰. 서비스별 목록은 `RESOLVED` 제외(해결된 스레드 비표시).
- 모아보기 페이징 쿼리 파라미터: `bigCategory`, `middleCategory`, `opinionType`, `status`, `mySide`, `page`, `size`.
  - `page` 는 1-base(비정상 값 → 1), `size` 는 1~100(비정상 → 20, 100 초과 → 100).
  - 응답은 `{ items, totalCount }`. 필터·정렬(미해결 우선)은 서버에서 수행한다.

### 8-3. 체크리스트 (2.0 신규)

| 기능 | Method | URL |
|---|---|---|
| 프로그램 점검 목록(마스터+상태) | GET | `/services/{serviceId}/checklist` |
| 점검 상태 갱신(업서트) | PATCH | `/services/{serviceId}/checklist/{checkPointId}` |
| 전 프로그램 매트릭스 | GET | `/checklist/matrix` |

| 성능(렌더) | 대용량 소스·매트릭스 가상 스크롤(보이는 행만 렌더), 소스 지연 로딩 |
| 성능(조회) | 모아보기 서버 페이징, 스레드 목록은 SQL `WHERE service_id` 필터(전체 스캔 제거) |
| 성능(전송) | `compression()` gzip 응답 압축 |
| 인코딩 | PB 소스 UTF-8 우선 → 실패 시 EUC-KR(CP949) 복원(원본 바이트 fetch) |
| 트랜잭션 | `@Transactional` + AsyncLocalStorage 단일 커넥션. **한 트랜잭션 안에서 SQL 동시 실행 금지**(순차 await — node-oracledb NJS-087) |
| 입력 검증 | 전역 `ValidationPipe({ whitelist, transform })` + DTO class-validator. 형식 오류 400, 미선언 필드 제거 |
| REST 규약 | 삭제 계열은 `204 No Content`(멱등) |
| 환경 전환 | `be/src/config/index.ts` 의 구현체 한 줄 교체로 MOCK ↔ Oracle 전환(기본값 MOCK — DB 없이 부팅) |
| 운영 보안 | 분류 매핑값 등 민감정보는 환경변수(`.env.*.local`)로 분리 |
| 접근성 | 스레드 헤더 키보드 토글(role/tabIndex/aria-expanded/Enter·Space), ESC 닫기는 window 리스너 한 곳으로 통일 |
| 배포 | ncc 단일 번들(oracledb Thin 포함)로 의존성 설치 없이 pm2 구동 |
