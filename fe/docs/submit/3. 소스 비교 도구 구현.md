## 1. 구현 개요

설계 문서의 컴포넌트/데이터 모델/Parser 전략을 기준으로 프론트엔드(비교·검증 UI)와 백엔드(카탈로그·토론·체크리스트 API)를 구현하였다. 핵심 비즈니스 로직(메서드 인식·점프, 검색, SQL 대응, 필터·페이징)은 **순수 함수 모듈로 분리**하여 테스트 가능하게 구성했다.

2026-07-08 에는 사내 개발 가이드(코딩/리팩토링/성능/REST/폴더구조/UI-UX) 기준으로 전체 코드 리뷰를 수행하여 심각도 순으로 조치하였고, 거대 모듈을 기능 폴더 단위로 재배치했다. 2026-08-05 에는 프론트·백엔드 저장소를 단일 저장소(`fe/`, `be/`, `docs/`)로 통합했다.

## 2. 프론트엔드 구현

### 2-1. 비교 대상 로딩
- `discussionService.getServices()`로 카탈로그를 받아 **분류 → 업무 → 프로그램명** 파생 목록을 구성.
- 프로그램명 선택 시 `resolveProgramFileName(parser)`로 PB/PB5 실제 파일명을 도출하고, `Link.ts`/`sourceLoad.ts` 로 자산을 지연 로딩.
- 자산 매칭은 경로가 아니라 **파일명(basename)** 기준이라 폴더가 몇 단계로 중첩되어도 동작한다(`code/c/**`, `code/java/**`).

### 2-2. 코드 렌더링 (CodeBlock)
- **Shiki**로 토큰화하여 색상/굵기/기울임을 적용(C/Java/XML/SQL 등 다언어). 토큰은 `Token`/`VisibleLine` 타입으로 명시.
- **TanStack Virtual**로 보이는 라인만 렌더 → 수천 라인도 부드럽게 스크롤.
- 라인 거터에 **접기 표식(▶/▼)**, **토론 마커(점 + 개수)**, 라인 번호 표시.
- 부모에 `scrollToLine` 핸들 노출(점프용).

### 2-3. 메서드 인식
- **C/Pro\*C**(`cMethodExtractor`): 괄호·중괄호 추적 기반으로 함수 정의를 추출. 프로토타입(`;`)·전처리기(`#define`)·구조체 파라미터·함수 포인터 반환형을 구분하고, 전처리기 블록으로 중괄호 깊이가 어긋나는 문제를 피하려 **depth-free** 방식으로 전환했다.
- **Java**(`javaMethodExtractor`): 시그니처를 이어 붙여 파라미터 `)` 와 본문 `{` 를 찾는 스캐너. K&R/Allman·제네릭 반환형·멀티라인 시그니처·생성자·어노테이션을 지원하고, 제어문/호출/익명 클래스/추상 메서드는 제외. 함수명과 여는 `(` 가 다른 줄에 있어도 인식한다.
- XML/SQL은 대상 메서드 없음으로 처리.

### 2-4. 메서드 점프
- 프로그램ID가 `파일.메서드` 형태면 로드 후 해당 메서드로 **자동 점프**.
- **좌·우 공유**: 한쪽 file_name만 메서드 형태여도 양쪽이 같은 메서드로 점프(이름 정규화 매칭이 snake_case ↔ camelCase 차이를 흡수).
- **Alt+클릭**: 클릭한 메서드에 대응되는 반대편 메서드로 이동.

### 2-5. 접기 / 검색 / 동기 스크롤 / 가독성
- 메서드 단위 접기/펼치기, 전체 접기/펼치기, **import/include 묶음 접기**(`importRegion`).
- **코드 내용 검색(Ctrl+F)**: 좌·우 패널이 각자 검색 상태를 가지며, `codeSearch` 가 매치 위치를 계산하고 Shiki 토큰을 매치 경계로 쪼개 하이라이트한다.
- 좌·우 동기 스크롤(휠/스크롤바, 오프셋 유지) — 가운데 분할선의 체인 버튼과 단축키로 토글.
- 글자 크기, 좌·우 패널 너비(드래그) 조절.

### 2-6. 토론(의견) UI
- 라인 마커 클릭 → 스레드 보기(본문 + 답글), `Shift+클릭` → 새 의견, 답글 작성.
- **의견 유형 5종**(불일치 의심/누락 의심/설명 요청/업무 확인 필요/기타)을 새 스레드 생성 시 강제 선택하고 배지로 표시(`config/opinionType.ts` 단일 정의).
- 마커 색상은 **PB/PB5 토글 색과 통일**: `CHECK_PB`=indigo, `CHECK_PB5`=emerald, `RESOLVED`=회색. 한 줄에 여러 스레드가 있으면 **미해결 우선**으로 대표색을 정하고 개수를 함께 표시(`markerSummary`).
- 스레드 종료(해결)는 확인 모달을 거쳐 처리(되돌릴 수 없는 작업 보호).

### 2-7. 의견 모아보기 (CommentBoard)
- 분류별/전체 스레드를 `GET /discussion-threads` 로 **서버 페이징** 조회하고, 페이지 번호 바(`pagination.ts`)로 이동.
- 유형·업무는 공유 칩 컴포넌트(`component/CategoryChips`)로 통일, 상태·의견 유형·즐겨찾기 필터를 함께 적용.
- 스레드를 펼치면 답글만 보이도록 원본 의견 중복 표시를 제거(`commentThread`), 정렬은 `commentSort`.
- **리액션**(확인중/조치 완료/조치 불필요)은 메시지 단위로 설정하고, 스레드 제목에는 마지막 리액션을 표시. 본인 측 글에는 리액션 불가·같은 팀 리액션은 숨김.
- **수정/삭제 가드**: 상대 측이 이후에 답글을 달았으면 수정·삭제 모두 차단.
- 스레드 헤더는 키보드로도 펼치기/접기 가능(role/tabIndex/aria-expanded/Enter·Space).

### 2-8. 체크리스트
- **패널(소스 비교 탭 좌측 슬라이드)**: 문항 단위로 5상태(선택안함/예/아니오/해당없음/판단 보류)와 메모를 입력. 카테고리 단위 접기, 열 너비 조절.
- **모아보기(ChecklistBoard)**: 프로그램 × 문항 매트릭스를 가상 스크롤로 렌더(2만 건급), 진행률·미판정 집계, 유형/업무 필터, 셀별 의견 표시. 읽기 전용이며 카드 모달은 ESC로 닫는다.
- 진행률은 `isDecided`(YES/NO/NA = 판단 완료) 기준으로 계산.

### 2-9. SQL 대응 보기
- PB5 Java의 매퍼 호출 줄을 인식해 hover 로 발견성을 주고, 클릭하면 슬라이드 패널에 **PB 인라인 EXEC SQL ↔ PB5 매퍼 XML** 을 나란히 표시(`sqlLink` + `SqlSlidePanel`).
- 매퍼 타입의 namespace 는 import 구역에서 도출하며, 못 찾으면 메서드명 기준으로 후보를 제시한다.

### 2-10. 즐겨찾기
- 프로그램(service_id) 즐겨찾기를 **localStorage** 로 관리(`favorites.ts` — 순수 함수와 입출력 분리). 선택바 ★ 토글·칩 행, 의견 모아보기 필터와 연동.

### 2-11. 인코딩 자동 복원 (Link.ts)
- 자산을 `?url`로 받아 원본 바이트를 fetch → UTF-8(엄격) 우선 디코딩, 실패 시 **EUC-KR(CP949)** 로 복원하여 PB 한글 깨짐 방지.

### 2-12. 공통 처리
- 에러 메시지 변환은 `errorMessage.ts` 로 통합(3개 컴포넌트 중복 제거), 서비스 계층은 응답 DTO 인터페이스 + 열거형 가드로 매핑해 유령 값을 차단한다.
- ESC 처리는 `CodeComparator` 의 window 리스너 한 곳에서 우선순위(한 번에 하나)를 관리한다.

## 3. 백엔드 구현 (NestJS 헥사고날)

- **port/in**(Controller·DTO) → **Service** → **port/out**(Repository) 단방향 의존. 모듈은 `services` / `discussion-threads` / `discussion-message` / `checklist` 4개.
- 리포지토리는 **Oracle 구현**과 **Mock(인메모리) 구현**을 동일 인터페이스로 제공하며, `config` 프로파일에 따라 주입한다(`common/repository.provider.ts`). 기본값은 MOCK 이라 DB 없이 부팅된다.
- **@Transactional**: AsyncLocalStorage에 트랜잭션 커넥션을 담아 한 트랜잭션 내 모든 SQL이 단일 커넥션을 공유, 커밋/롤백을 일원화. 단일 커넥션에서는 SQL을 **순차 실행**한다.
- **조회(B 뷰)**: 스레드 + 첫 메시지(MIN id)를 JOIN. 서비스별 목록은 SQL 단계에서 `service_id` 로 필터하고 `RESOLVED` 를 제외한다.
- **모아보기**: 분류/업무/의견 유형/상태/내 소속 필터와 페이징(offset 기반)을 SQL에서 처리하고 `{ items, totalCount }` 로 응답.
- **체크리스트**: 점검 항목 마스터(check_point)와 프로그램별 상태(check_list)를 조인해 내려주고, PATCH 는 `(check_point_id, service_id)` 업서트로 처리. 매트릭스는 전 프로그램 × 문항을 한 번에 조회.
- **공통**: KST 시각 SQL 표현식을 `common/sql-expressions.ts` 로 공유, 전역 `ValidationPipe`, `compression()` gzip, DELETE 계열 204 응답.
- **Oracle 연동**: oracledb Thin 모드, CLOB은 문자열로 페치.
- **배포**: ncc로 oracledb까지 단일 번들(`be_next`) → pm2 구동(.env/npm install 불필요).

## 4. Parser 구현
- 공통 인터페이스(`supports`/`parse`) 기반의 전략 패턴으로 PB/PB5 각각 레지스트리 구성, fallback(Default)은 항상 마지막.
- 분류↔Parser 매핑은 환경변수(`config/categoryMap`)로 주입, 미설정 시 개발 폴백값 사용.

## 6. 코드 구조 (요약)

```
fe/ (프론트엔드)
└─ src/
   ├─ App.tsx · main.tsx          # 탭 구성(소스 비교 / 의견 모아보기 / 체크리스트 모아보기)
```
