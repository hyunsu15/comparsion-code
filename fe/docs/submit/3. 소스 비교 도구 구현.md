## 1. 구현 개요

설계 문서의 컴포넌트/데이터 모델/Parser 전략을 기준으로 프론트엔드(비교·검증 UI)와 백엔드(카탈로그·토론 API)를 구현하였다. 핵심 비즈니스 로직(메소드 인식·점프)은 **순수 함수 모듈로 분리**하여 테스트 가능하게 구성했다.

## 2. 프론트엔드 구현

### 2-1. 비교 대상 로딩
- `discussionService.getServices()`로 카탈로그를 받아 **대분류 → 중분류 → 프로그램명** 파생 목록을 구성.
- 프로그램명 선택 시 `resolveProgramFileName(parser)`로 PB/PB5 실제 파일명을 도출하고, `resolveSourceContent(Link.ts)`로 자산을 지연 로딩.

### 2-2. 코드 렌더링 (CodeBlock)
- **Shiki**로 토큰화하여 색상/굵기/기울임을 적용(C/Java/XML/SQL 등 다언어).
- **TanStack Virtual**로 보이는 라인만 렌더 → 수천 라인도 부드럽게 스크롤.
- 라인 거터에 **접기 표식(▶/▼)**, **토론 마커(점)**, 라인 번호 표시.
- 부모에 `scrollToLine` 핸들 노출(점프용).

### 2-3. 메소드 인식 (methodJump.ts)
- **C/Pro\*C**: 괄호·중괄호 추적 기반으로 함수 정의 추출. 프로토타입(`;`)·전처리기(`#define`)·구조체 파라미터를 구분.
- **Java**: 시그니처를 이어 붙여 파라미터 `)` 와 본문 `{` 를 찾는 스캐너로 추출. K&R/Allman(중괄호 다음 줄)·제네릭 반환형(공백 포함)·멀티라인 시그니처·생성자·어노테이션을 지원하고, 제어문/호출/익명클래스/추상 메소드는 제외.
- XML/SQL은 대상 메소드 없음으로 처리.

### 2-4. 메소드 점프
- 프로그램ID가 `파일.메소드` 형태면 로드 후 해당 메소드로 **자동 점프**.
- **좌·우 공유**: 한쪽 file_name만 메소드 형태여도 양쪽이 같은 메소드로 점프(이름 정규화 매칭이 snake_case ↔ camelCase 차이를 흡수).
- **Alt+클릭**: 클릭한 메소드에 대응되는 반대편 메소드로 이동(좌우 메소드 매칭).

### 2-5. 접기 / 동기 스크롤 / 가독성
- 메소드 단위 접기/펼치기, 전체 접기/펼치기.
- 좌·우 동기 스크롤(휠/스크롤바, 오프셋 유지) 토글.
- 글자 크기, 좌·우 패널 너비(드래그) 조절.

### 2-6. 토론(코멘트) UI
- 라인 마커 클릭 → 스레드 보기(본문 + 답글), `Shift+클릭` → 새 댓글, 답글 작성.
- 마커 색상은 **PB/PB5 토글 색과 통일**: `CHECK_PB`=indigo, `CHECK_PB5`=emerald, `RESOLVED`=회색.
- 스레드 종료(해결)는 확인 모달을 거쳐 처리(되돌릴 수 없는 작업 보호).

### 2-7. 인코딩 자동 복원 (Link.ts)
- 자산을 `?url`로 받아 원본 바이트를 fetch → UTF-8(엄격) 우선 디코딩, 실패 시 **EUC-KR(CP949)** 로 복원하여 PB 한글 깨짐 방지.

## 3. 백엔드 구현 (NestJS 헥사고날)

- **port/in**(Controller·DTO) → **Service** → **port/out**(Repository) 단방향 의존.
- 리포지토리는 **Oracle 구현**과 **Mock 구현**을 동일 인터페이스로 제공(개발/테스트는 Mock).
- **@Transactional**: AsyncLocalStorage에 트랜잭션 커넥션을 담아 한 트랜잭션 내 모든 SQL이 단일 커넥션을 공유, 커밋/롤백을 일원화.
- **조회(B 뷰)**: 스레드 + 첫 메시지(MIN id)를 JOIN. 서비스 계층에서 serviceId 필터 + `RESOLVED` 제외.
- **Oracle 연동**: oracledb Thin 모드, CLOB은 문자열로 페치, KST 시각 기록.
- **배포**: ncc로 oracledb까지 단일 번들 → pm2 구동(.env/npm install 불필요).

## 4. Parser 구현
- 공통 인터페이스(`supports`/`parse`) 기반의 전략 패턴으로 PB/PB5 각각 레지스트리 구성, fallback(Default)은 항상 마지막.
- 대분류↔Parser 매핑은 환경변수(`config/categoryMap`)로 주입, 미설정 시 개발 폴백값 사용.

## 5. 주요 기술 이슈 및 해결

| # | 이슈 | 원인 | 조치 |
|---|---|---|---|
| 1 | PB 메소드/프로그램명 점프 미동작 | 좌·우가 각자 file_name에서만 점프 대상 추출 → PB는 실제 `.pc`라 항상 없음 | `resolveJumpTargets`로 좌·우 점프 대상 공유 + `resolveProgramFileName` pb 분기 대칭화 |
| 2 | Java 메소드 인식 누락(들쑥날쑥) | 단일 줄 정규식이 Allman 중괄호·제네릭 공백·멀티라인 시그니처를 못 잡음 | 괄호/중괄호 추적 스캐너로 재작성 |
| 3 | PB 메소드 인식 오류 | 파라미터의 `struct`가 함수명을 가로채고, `#define`/익명 구조체를 오인 | 함수명은 `(` 앞에서만 추출, 전처리기 라인 제외, 익명 구조체 제외 |
| 4 | 점프 locator에 확장자 혼입 | 매핑값에 `.pc`/`.c`가 남아 `X.pc.method` 형태로 매칭 깨짐 | 매핑값의 `.pc`/`.c` 접미사 제거 |
| 5 | 토론 마커 색상 구분 | 상태별 시각 구분 필요 | 상태별 색상 + PB/PB5 토글 색과 통일 |
| 6 | (Oracle) 댓글/답글 작성 시 오류 | 메시지 생성이 단일 트랜잭션 커넥션에서 `Promise.all`로 두 SQL 동시 실행(node-oracledb 금지) | `Promise.all` → 순차 await 로 변경 |

## 6. 코드 구조 (요약)

```
comparsionV2 (FE)
└─ src/
   ├─ CodeComparator.tsx     # 컨테이너(상태/오케스트레이션)
   ├─ CodeBlock.tsx          # 토큰 렌더 + 가상 스크롤 + 마커/접기
   ├─ methodJump.ts          # 메소드 추출/점프/매칭 (순수 함수)
   ├─ Link.ts                # 자산 매칭/지연로딩/인코딩 복원
   ├─ parser/                # 대분류별 file_name 해석 전략
   ├─ config/                # categoryMap 등 (환경변수 주입)
   └─ discussionService.ts   # BE REST 연동

comparsion-be (BE, NestJS 헥사고날)
└─ src/
   ├─ services/              # 비교 대상 카탈로그
   ├─ discussion-threads/    # 스레드 (port in/out, service)
   ├─ discussion-message/    # 메시지(댓글) (port in/out, service)
   └─ db/                    # SQLTemplate / TransactionManager / Pool
```
